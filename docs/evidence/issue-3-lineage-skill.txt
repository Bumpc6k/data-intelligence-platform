本项过程中发现并修掉的缺陷（自报）
==================================
1. **`receipt.usable` 没有出现在序列化结果里**。
   最初写成普通 property，`model_dump_json()` 里根本没有它 —— 外壳拿到的 JSON 少一个
   判断依据（"成功且至少有一条证据"），只能自己猜规则。端到端演示断言
   payload["receipt"]["usable"] 时直接 KeyError 才暴露。已改为 `@computed_field`，
   并补了回归测试 tests/test_skill_receipt.py::test_usable_is_present_in_serialized_json。

环境侧发现（不属本 Issue，供排障参考）
=====================================
**内核启动脚本走 tmux 时会静默死掉**：ops/start-lineage-api.sh 先 export PYTHONPATH 再
`tmux new-session`，但 tmux **不继承** PYTHONPATH（它只在默认 update-environment 列表里的变量
才继承）。实测：

$ tmux show-environment -g PYTHONPATH
unknown variable: PYTHONPATH
$ # 客户端 export PYTHONPATH 后新建会话，会话内：
会话内 PYTHONPATH=（空）

于是内核以 ModuleNotFoundError 退出，脚本却已经报了"会话已启动"，看起来像起了其实没起。
本环境的绕开方式（不经过 tmux）：

$ PYTHONPATH="$PWD:$PWD/apps/lineage-api:$PWD/packages/lineage-core" \
    nohup .venv/bin/python -m lineage.serve.api_server --host 127.0.0.1 --port 18080 > /tmp/lineage-api.log 2>&1 &

$ curl -sS --noproxy '*' http://127.0.0.1:18080/health
{"success": true, "service": "lineage-api", ..., "kb_metrics": 75, "graph_exists": true, ...}
