验收 ②：网关不可达时明确报错，不静默失败
=========================================
**真实 HTTP 验证**（把 LLM_BASE_URL 指到必然连不上的 127.0.0.1:1，起第二个网关实例）：

$ curl http://127.0.0.1:18201/health
{"ok":true,"service":"model-gateway","version":"0.1.0","base_url":"http://127.0.0.1:1",
 "model":"deepseek-v4-flash","key_configured":true,"timeout":30.0,"max_attempts":2,
 "rate_limit_per_min":0}

$ curl -X POST http://127.0.0.1:18201/v1/chat/completions -d '{"messages":[...]}'
{"error":{"type":"gateway_error","code":"upstream_error",
          "message":"网关不可达：http://127.0.0.1:1（ConnectError）"}}
HTTP 502

$ curl http://127.0.0.1:18201/usage
{"calls":1,"failures":1,...,"recent":[{"model":"deepseek-v4-flash","ms":130,"attempts":2,
  "ok":false,...,"http_status":502,
  "error":"网关不可达：http://127.0.0.1:1（ConnectError）"}]}

要点：① 502 + 机器可读的 `code`；② **attempts=2** 证明连接类错误重试过；
③ 失败进了记账（failures=1）；④ **没有任何"规则模式"降级**。


反例清单（都在单测里，全部通过）
================================
| 场景 | 期望 | 用例 |
| --- | --- | --- |
| 未配 key | 503 / `no_api_key`，且**不打上游** | test_missing_key_fails_loudly_and_never_calls_upstream |
| 未配模型 | 503 / `no_model`，且不打上游 | test_missing_model_fails_loudly |
| `stream=true` | 400 / `stream_unsupported`，**不静默降级成非流式** | test_stream_is_rejected_not_silently_downgraded |
| 上游 4xx | 照实回报上游原文，**不重试** | test_upstream_error_is_reported_verbatim_and_not_retried |
| 连接错误 | 重试到上限（attempts=max） | test_connect_error_is_retried_up_to_max_attempts |
| 读超时 | **不重试**（避免重复计费），attempts=1 | test_read_timeout_is_not_retried |
| 触发限流 | 429 / `rate_limited` | test_rate_limit_placeholder_blocks_then_recovers |
| 请求体非 JSON / 非对象 | 400 / `bad_json` / `bad_payload` | test_http_bad_payloads_are_400 |

不泄密（两个方向都测）：
- `test_key_never_leaks`：key 不出现在 /health、错误消息里；
- `test_key_is_sent_as_bearer_to_upstream`：对照证明 key 确实用上了（否则"不泄密"就变成"没用上"）。


边界声明（按 Issue 的「不要做」）
================================
- **不做提示词工程**：请求体除 `model` 外原样转发（test_request_body_is_forwarded_untouched_except_model）。
- **不做多轮对话编排**：网关不保存任何会话状态。
- **不把 key 写进仓库**：`.env` 本地文件（`git check-ignore -v .env` → `.gitignore:9:.env`），
  仓库里只有 `.env.example` 占位。


自报的两处需要评审知道
======================
1. **扩展了 `dip_core.config.Settings`（新增 5 个字段，全部带默认值、向后兼容）**，
   而不是在网关里另起一套配置读取 —— 因为该模块的定位就是"配置只有一处真相"，
   `apps/portal-api/.../settings.py` 也明确写了"避免两处配置真相"。
2. **与 v1 的 ADR-0004 相反**：ADR-0004 是"未配 key 进规则模式"，而本项按
   《v2 项目规划 v1》§6「已决定不保留无模型降级」实现 —— 未配 key 一律 503 明确报错。
   这是 v2 有意推翻 v1 的决定，已在 `dip_core/config.py` 的注释与 PR 里写明。
   顺带说清：`.env` 读到的 key 是我从本机 Hermes 配置里取的（**未打印、未入库**），
   仅用于一次真实调用验证；正式使用请换成项目自己的 key。
