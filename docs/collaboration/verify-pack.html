2. 任务卡

T1 把 DeepSeek Harness（dsh）跑起来

项内容
验证什么这个开源 harness 能不能在我们的环境真跑起来、能不能当插件运行时与 Web 壳
交付物① docs/notes/dsh-setup.md：从零到能对话的完整步骤（含踩坑与解决办法）② 版本锁定写法（不追 latest）③ 一张"能对话"的截图或录屏
边界不要做鉴权、多用户、生产部署；不要改 dsh 源码；不要接我们的业务 skill（那是 T2）
验收标准新人照着 docs/notes/dsh-setup.md 能一次跑通；文档里写明 Node/pnpm 版本、dsh 版本、启动命令、端口
提示仓库：github.com/deepseek-ai/deepseek-harness（MIT，TypeScript + Cordis，v0.1 预览版）

T2 把一个业务 skill 经 MCP 被外壳调用

项内容
验证什么"万物皆插件"能不能落地：我们的能力包成 MCP skill 后，能否被 dsh 这类外壳无差别调用
交付物① 一个 MCP skill 服务，包装现成的血缘解析（内核 POST /analyze，只读）② 该 skill 的契约声明（按《架构讨论》§3 字段：name/when/input/output/side_effect/evidence_kind/renderer/timeout/idempotent/budget）③ docs/notes/mcp-skill.md：怎么注册、怎么被调用、返回长什么样
边界只包装 1 个 skill，不要批量包装；不要碰写操作类能力（建表/调度那些留给后续）
验收标准给一句「ads.ads_产销存月报 的产量怎么来的？」能返回结构化结果 + 回执（来源端点、耗时、证据条数）；bash ops/gate.sh 绿；有测试用例（可用已录制的真实响应做假内核）
提示已录制的真实内核响应 fixture：integrations/lineage-client/tests/fixtures/kernel-probe-2026-09-23.json；内核服务起法见 §3

T3 模型网关（薄层）+ 出口事实校验

项内容
验证什么① 能稳定接 DeepSeek API ② "模型不许编"这件事能用机制做到（不是靠提示词）
交付物① 薄模型网关：统一 OpenAI 兼容入口（换模型/限流/记账不改业务）② 出口事实校验器：只允许用回执里出现过的表名、字段名、数字组答案；越界即拦截并标记 ③ 测试：构造"模型编了一个不存在的表名/数字"的输入，断言被拦截
边界不要做提示词工程调优；不要做多轮对话；只做"网关 + 校验器 + 测试"
验收标准拦截测试通过（给出反例与正例各 3 个）；网关能在不改进业务代码的前提下换模型（给一段配置即可切换）；bash ops/gate.sh 绿
提示校验器可以独立于模型实现（入参：模型输出文本 + 回执白名单），这样最好测

T4 智能防火墙最小版（独立服务）

项内容
验证什么三档判定 + 一次性令牌 + 全量留痕，能不能独立成服务并真拦住危险动作
交付物① 独立服务（单独的进程/容器，提供 HTTP 接口：判定 与 校验令牌）② 策略表（可配置：动作 → 档位）③ 判定与审批落审计库（复用现有 dip-pg）④ docs/notes/firewall.md：三档定义、策略怎么改
边界不要做审批流程引擎/多人流转（P1 只保留"上一级确认一次"）；不要接入真实调度平台写操作
验收标准① truncate table x / drop table x → 拒绝；② 生产写（如"上线工作流"）→ 需审批；③ 只读查询 → 自动通过；④ 令牌不可复用（用两次第二次被拒）；⑤ 四次判定全部在审计库里能查到（含判定依据与审批人）
提示三档定义见《架构讨论》§2.2 与架构图 v3 的判定表；跨环境动作并入"需审批"档

4. 验收方式（谁验、怎么验）

验收人：项目负责人（Hermes 代跑）。流程：协作者提 PR → 我跑门禁 + 按任务卡的验收标准逐条执行 → 逐条给"通过/不通过 + 证据" → 全通过才合并，否则打回并写明原因。

逐条存证要求（验收只看这些）：

1. 命令 + 原始输出（贴在本包 §5 的回报表里，或存 docs/evidence/tN-*.txt|png）

2. 测试文件路径 + pytest 通过输出

3. 关键行为的反例（如 T3 的"编表名被拦"、T4 的"truncate 被拒"）
