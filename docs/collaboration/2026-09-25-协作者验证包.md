## 1. 共同规则（四个任务都适用）

| 规则 | 说明 |
| --- | --- |
| **独立可完成** | 四个任务互不依赖，不需要等别人；**不要顺手改别人的范围** |
| **冻结资产只调用、不修改** | 内核仓库、`integrations/lineage-client`、`packages/dip-contracts`、审计与知识库**只读复用**（见附录） |
| **一个任务一个 PR** | 分支 `feat/tN-简述`；PR 必须写清"**怎么验证**"（命令 + 期望输出） |
| **门禁必须绿** | `bash ops/gate.sh` → `GATE: ALL_PASS`（含 ruff + pytest + 分层守卫）；**红了不许提 PR** |
| **不许提交密钥** | DeepSeek Key 等放 `.env`（已在 .gitignore）；仓库里只留 `.env.example` |
| **事实不许编** | 任何结论必须能指到来源（文件/端点/行号）；拿不到就明说"没查到" |
| **时间盒一周** | 到期没跑通**不要硬撑**：交"卡在哪 + 已获得的证据 + 需要什么支持" |

## 2. 任务卡

### T1 把 DeepSeek Harness（dsh）跑起来

| 项 | 内容 |
| --- | --- |
| **验证什么** | 这个开源 harness 能不能在我们的环境真跑起来、能不能当插件运行时与 Web 壳 |
| **交付物** | ① `docs/notes/dsh-setup.md`：从零到能对话的完整步骤（含踩坑与解决办法）② **版本锁定**写法（不追 latest）③ 一张"能对话"的截图或录屏 |
| **边界** | **不要**做鉴权、多用户、生产部署；**不要**改 dsh 源码；**不要**接我们的业务 skill（那是 T2） |
| **验收标准** | 新人照着 `docs/notes/dsh-setup.md` 能一次跑通；文档里写明 Node/pnpm 版本、dsh 版本、启动命令、端口 |
| **提示** | 仓库：`github.com/deepseek-ai/deepseek-harness`（MIT，TypeScript + Cordis，v0.1 预览版）|

### T2 把一个业务 skill 经 MCP 被外壳调用

| 项 | 内容 |
| --- | --- |
| **验证什么** | "万物皆插件"能不能落地：我们的能力包成 **MCP skill** 后，能否被 dsh 这类外壳无差别调用 |
| **交付物** | ① 一个 MCP skill 服务，包装**现成的血缘解析**（内核 `POST /analyze`，只读）② 该 skill 的**契约声明**（按《架构讨论》§3 字段：name/when/input/output/side_effect/evidence_kind/renderer/timeout/idempotent/budget）③ `docs/notes/mcp-skill.md`：怎么注册、怎么被调用、返回长什么样 |
| **边界** | 只包装 1 个 skill，**不要**批量包装；**不要**碰写操作类能力（建表/调度那些留给后续） |
| **验收标准** | 给一句「ads.ads_产销存月报 的产量怎么来的？」能返回结构化结果 **+ 回执**（来源端点、耗时、证据条数）；`bash ops/gate.sh` 绿；有测试用例（可用已录制的真实响应做假内核） |
| **提示** | 已录制的真实内核响应 fixture：`integrations/lineage-client/tests/fixtures/kernel-probe-2026-09-23.json`；内核服务起法见 §3 |

### T3 模型网关（薄层）+ 出口事实校验

| 项 | 内容 |
| --- | --- |
| **验证什么** | ① 能稳定接 DeepSeek API ② **"模型不许编"这件事能用机制做到**（不是靠提示词） |
| **交付物** | ① 薄模型网关：统一 OpenAI 兼容入口（换模型/限流/记账不改业务）② **出口事实校验器**：只允许用**回执里出现过的**表名、字段名、数字组答案；越界即拦截并标记 ③ 测试：构造"模型编了一个不存在的表名/数字"的输入，**断言被拦截** |
| **边界** | **不要**做提示词工程调优；**不要**做多轮对话；只做"网关 + 校验器 + 测试" |
| **验收标准** | 拦截测试通过（给出反例与正例各 3 个）；网关能在不改进业务代码的前提下换模型（给一段配置即可切换）；`bash ops/gate.sh` 绿 |
| **提示** | 校验器可以独立于模型实现（入参：模型输出文本 + 回执白名单），这样最好测 |

### T4 智能防火墙最小版（独立服务）

| 项 | 内容 |
| --- | --- |
| **验证什么** | 三档判定 + 一次性令牌 + 全量留痕，能不能独立成服务并真拦住危险动作 |
| **交付物** | ① 独立服务（单独的进程/容器，提供 HTTP 接口：`判定` 与 `校验令牌`）② 策略表（可配置：动作 → 档位）③ 判定与审批**落审计库**（复用现有 `dip-pg`）④ `docs/notes/firewall.md`：三档定义、策略怎么改 |
| **边界** | **不要**做审批流程引擎/多人流转（P1 只保留"上一级确认一次"）；**不要**接入真实调度平台写操作 |
| **验收标准** | ① `truncate table x` / `drop table x` → **拒绝**；② 生产写（如"上线工作流"）→ **需审批**；③ 只读查询 → **自动通过**；④ 令牌**不可复用**（用两次第二次被拒）；⑤ 四次判定全部在审计库里能查到（含判定依据与审批人） |
| **提示** | 三档定义见《架构讨论》§2.2 与架构图 v3 的判定表；跨环境动作并入"需审批"档 |

## 3. 上手说明（环境）

```bash
# 现有可复用服务（都在本机，幂等脚本）
bash ops/start-pg.sh                      # 审计库 PostgreSQL :15432（会话/审计已能用）
bash /usr/local/bin/start-lineage-api.sh  # 数据智能内核 :18080（血缘/口径/报告，只读）
bash ops/start-portal.sh                  # 平台后端 + 前端 :18100（http://127.0.0.1:18100/app/）

# 开发
make venv          # 建虚拟环境（python3.10；缺 ensurepip 先 apt install python3.10-venv）
bash ops/gate.sh   # 一键验收：lint + 测试（提交前必须绿）
bash ops/gate.sh --with-smoke   # 带上真内核的冒烟测试
```

**代码结构**（`data-intelligence-platform`）：`apps/portal-api`（后端）、`apps/portal-web`（前端）、`packages/dip-contracts`（契约层）、`packages/dip-agent`（编排）、`integrations/lineage-client`（内核客户端）、`docs/adr`（决策记录）。
**分层铁律**：依赖只能自上而下（有测试强制），契约层不许引重量级依赖。

**`.env.example` 建议内容**（新任务如需要新建）：

```
DEEPSEEK_API_KEY=sk-xxx            # 不要提交真实值
DEEPSEEK_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
DIP_PG_DSN=postgresql://dip:dip@127.0.0.1:15432/dip
LINEAGE_BASE_URL=http://127.0.0.1:18080
```

## 4. 验收方式（谁验、怎么验）

**验收人：项目负责人（Hermes 代跑）**。流程：协作者提 PR → 我跑门禁 + **按任务卡的验收标准逐条执行** → 逐条给"通过/不通过 + 证据" → 全通过才合并，否则打回并写明原因。

**逐条存证要求**（验收只看这些）：
1. 命令 + 原始输出（贴在本包 §5 的回报表里，或存 `docs/evidence/tN-*.txt|png`）
2. 测试文件路径 + `pytest` 通过输出
3. 关键行为的反例（如 T3 的"编表名被拦"、T4 的"truncate 被拒"）
