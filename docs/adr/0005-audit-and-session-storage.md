# ADR-0005：审计与会话用 PostgreSQL，且只有 API 层碰数据库

- 状态：**已采纳**（2026-09-23）
- 相关：工作项 W-117（审计）、W-112（会话）

## 背景

"可追溯"是本产品的核心主张：无凭证不发布。但没有**留痕**的可追溯只是当场可追溯——
刷新页面、重启服务后，"谁在什么时候问了什么、平台调了内核哪几个端点、拿回来哪些证据"全都消失。

## 决策

1. 用 **PostgreSQL**（P1 唯一的库，与规划一致），容器 `dip-pg`，端口 127.0.0.1:15432。
2. 三张表：`sessions`（会话）/ `messages`（消息，含完整 answer JSONB）/ `audit_log`（审计，含证据与工具调用明细）。
3. **只有 `apps/portal-api` 知道数据库**：审计写入发生在拿到 `Answer` 之后；
   `dip-agent` 保持纯粹，不 import 任何数据库代码（由分层守卫测试强制）。
4. P1 用 psycopg3 + 启动时幂等建表（`CREATE TABLE IF NOT EXISTS`），**暂不引 Alembic**。
5. 数据库不可用时：问答仍然工作（只是不留痕），接口返回 `success=false` 与原因，界面须显示"未落库"。

## 后果

- 好：审计可查、会话可续（刷新页面后追问不断）；分层不被污染；演示可复现。
- 代价：多一个有状态组件（PG）；表结构变更时需手动迁移——等出现真实迁移需求再引 Alembic。

## 被否掉的备选

- SQLite 落盘：省一个组件，但 P1 规划里 PG 已在栈内，且后续权限/审批都要关系型能力。
- 写进日志文件：不可检索、不可关联（"这条回答对应哪次调用"要靠猜）。
